# Architecture Review

Review 基准：社区贡献安全、插件自由度、协议边界、故障恢复、供应链、测试和可维护性。评分只计算仓库中已实现并由测试或 CI 约束的能力。

## 评分：96 / 100

| 领域 | 得分 | 证据 |
|---|---:|---|
| 隔离与信任边界 | 19/20 | opaque sandbox、随机 channel、MessagePort、权限白名单、可信运行时分级 |
| 自动发现与贡献体验 | 15/15 | 单目录描述文件、glob 自动发现、ID/版本/权限校验、CODEOWNERS |
| SDK 与协议 | 14/15 | SDK v1、双向类型、严格事件 schema、会话绑定、早期事件队列 |
| 生命周期与故障控制 | 14/15 | ready 握手、10 秒超时、重开换会话、Error Boundary、可恢复 UI、宿主状态机 |
| CI、安全、性能与许可证 | 19/20 | 官方 npm 锁源、0 漏洞审计、依赖/许可证 Review、固定 Action SHA、CodeQL、CSP、逐文件 SPDX+SHA-256、体积与 300 行门禁 |
| 测试 | 10/10 | 24 个单元/集成测试加 6 个桌面/移动 Chromium 测试，覆盖握手、伪造消息、确认扣生命和响应式布局 |
| 可维护性 | 5/5 | 所有手写文件低于 300 行，加载器按职责拆分，完整文档 |

## 未得满分的原因

- opaque iframe 仍共享浏览器主线程调度，浏览器无法提供硬 CPU 配额。高风险游戏应部署到独立子域并继续审核。
- SDK 目前随主站发布，尚未成为有独立兼容矩阵和弃用周期的 npm 包。
- 商业账户、奖励、广告和支付尚未接入服务端，因此不能作为可信商业记账系统。

## 96 分验收证据

`npm run check` 必须同时通过 24 个单元/集成测试、6 个 Chromium 测试、零警告 Lint、TypeScript/Vite 构建、描述文件、逐文件资产哈希、300 行限制与包体预算。GitHub Actions 在每个 PR 重复执行门禁，CodeQL 每周和每次 PR 扫描。

该分数描述的是开源前端插件地基，不代表任何第三方游戏代码可以免审合并。未知贡献默认只能进入 opaque runtime，可信模块和弱化沙箱配置必须由仓库所有者审批。
