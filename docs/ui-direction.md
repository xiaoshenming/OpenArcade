# OpenArcade UI 方向

## 目标

OpenArcade 的第一屏是可直接游玩的游戏厅，不是开发者控制台或营销落地页。视觉需要同时传达轻松、可信、开放，并让游戏画面始终是最大的信息层级。

## 调研参考

- [Poki](https://poki.com/)：大众浏览器游戏平台。值得借鉴低摩擦进入、缩略图驱动发现和“游戏优先”的页面层级，不复制其品牌或素材。
- [Playnite](https://github.com/JosefNemec/Playnite)：MIT 开源游戏库管理器。值得借鉴封面库、当前游戏焦点和紧凑工具栏。
- [Pegasus Frontend](https://github.com/yeager/pegasus-frontend)：GPL-3.0+ 可定制游戏前端。适合作为主题系统和跨设备导航参考；GPL 代码不能直接并入本项目的 MIT 源码。
- [shadcn/ui](https://github.com/shadcn-ui/ui)：MIT 开源组件集合。未来增加账户、设置和后台表单时可以按需采用；当前游玩界面保持轻量自有 CSS，避免模板感和额外依赖。

## 采用方向：明亮的现代游戏房间

- 中性灰白画布，搭配珊瑚红、青绿、金黄和游戏自身颜色，不使用单一色调。
- 使用真实游戏画面作为入口缩略图，用户在选择前就能理解玩法。
- 桌面端采用轻量游戏库加大型游戏舞台；移动端游戏库横向滚动，始终可见。
- 边框、圆角和阴影只用于重复游戏项、游戏舞台、工具按钮和对话框。
- 移除 BUILD、运行容器和 SDK 类型等开发信息，技术说明留在文档。
- 声音、暂停、重开和全屏使用统一 Lucide 图标、tooltip 与可访问标签。

## 不采用

- 不直接套用完整仪表盘模板：它会让游戏厅变成运营后台。
- 不复制商业平台的素材、布局代码或品牌表达。
- 不引入重型游戏启动器代码：Playnite 和 Pegasus 面向桌面客户端，运行模型与 Web 插件宿主不同。
- 不使用大面积深色机柜、米色复古纸张或高密度工程标签作为默认主题。

## 验证基线

- 1440 x 1000：游戏舞台宽度约 1000px，游戏画面高 500px。
- 390 x 844：页面无横向溢出，游戏列表可横滑，游戏舞台在首屏内完整出现。
- 所有文字保持正常字距；所有手写文件继续低于 300 行。
- UI 变更必须通过单元测试、Lint、构建、质量门禁及桌面/移动 Chromium E2E。
